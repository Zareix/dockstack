---
title: Compose validation
---

Dockstack validates the Compose file and `.env` continuously while you edit the Files tab. Validation is informational: saving never blocks on it, even when the files are invalid.

## When it runs

- When the stack page opens, the saved files are validated.
- Every edit is validated immediately.
- On save, the same diagnostics are returned with the response.

Draft validation runs `docker compose config` with `--project-directory` and a temporary env file, so the stack directory is not touched. The command has a 10-second timeout.

## Results

| Result                     | Meaning                                                                                              |
| -------------------------- | ---------------------------------------------------------------------------------------------------- |
| No alert                   | The files are valid and no static warning was found.                                                 |
| **Validation failed**      | `docker compose config` failed. The alert lists the error lines reported by Compose.                |
| **Compose warnings**       | Compose warnings, plus Dockstack static checks.                                                     |
| **Env variables**          | Missing or unused keys in `.env`. See below.                                                        |

Errors and warnings are cleaned up, limited to 20 lines, and shown one per line.

## Environment variables

Dockstack scans the Compose file for `${VAR}` and `$VAR` references:

- **Missing** — referenced without a default (`:-` / `-`), absent from `.env` and from the Dockstack process environment. `Add to .env` appends the missing keys with empty values to the editor.
- **Unused** — keys present in `.env` but not referenced by the Compose file. `Clear unused` removes them from the editor.

`$$` escapes are ignored. Variables provided by the host environment are not reported as missing. These checks are best-effort: references inside YAML comments count, and `env_file` contents are not analyzed.

## Static warnings

Alongside `docker compose config`, Dockstack checks the resolved Compose model:

- **Duplicate published ports** between services of the same stack.
- **Host port already in use** by a running container from another stack. Containers from the current stack are ignored.
- **Image resolution** — referenced images are resolved through the Docker daemon and the registry. Not found, unauthorized and private images without credentials are reported. No image is pulled; results are cached (1 hour on success, 5 minutes on failure).

Port checks respect tcp/udp and host IP bindings (`0.0.0.0` / `::` conflict with specific addresses, distinct specific addresses do not).
